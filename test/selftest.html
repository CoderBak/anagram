6 · Long paragraph (>1500 chars — the HF-abstract regression)

Modern language model training pipelines increasingly rely on other models at every stage of their construction, using them to generate synthetic data, to filter enormous crawled corpora, to judge candidate outputs during preference tuning, and to guide countless small development decisions that never make it into the final report. These dependencies form a sprawling and largely undocumented graph that connects hundreds of public artifacts across model families, dataset releases, and evaluation suites, and the connections are often visible only through a stray sentence in an appendix, a configuration file in a repository, or an offhand remark in a community discussion thread. Mapping that graph by hand is slow and error-prone, because the evidence is scattered, the naming is inconsistent, and the same artifact frequently appears under several different identities that must be resolved before any structural analysis can begin. An automated approach must therefore read the documentation the way a careful human reviewer would, following references across papers, model cards, and code, while keeping track of exactly which claim came from which source and how confident it is entitled to be about each recovered edge in the graph. The system described here does precisely that, and it matters for this test page for one specific reason: this paragraph is deliberately written to run well past fifteen hundred characters so that any walker which still truncates a unit at a fixed character cap will visibly stop partway through, whereas the correct behaviour is a single badge whose underline runs all the way to the final LONGTAIL sentence at the very end of the paragraph.
