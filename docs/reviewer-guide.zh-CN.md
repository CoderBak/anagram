# 审核与全新配置验证

使用 [Anagram Releases](https://github.com/CoderBak/anagram/releases) 中版本相同的插件
ZIP 和本地组件。开发分支的未发布修改不等于线上版本；验证源码时请构建当前分支，
不要把旧版公开组件当成已经具备新功能的组件。

1. 在全新 Chrome 配置中安装。必需权限为 `storage`、`activeTab`、`contextMenus`、
   `scripting`、`nativeMessaging`、`webNavigation` 和 `webRequest`。后两项用于识别 PDF
   导航和响应元数据；网站和本地文件访问仍为可选，安装时均不授予。首次安装打开引导页。
2. 引导页说明独立本地组件、按设备选择的推荐模型（通常约 1.43 GB，含语言识别）及额外 Python/依赖、安装位置和删除方式。
   可以先查看链接中的对应版本脚本，再执行页面显示的一次性命令。命令包含当前插件 ID，
   无需管理员或 HF 账户；浏览器不能静默安装本地可执行程序。
3. 回到引导页，查看设备检测、计划/文件/体积及校验阶段；准备字节包含复用文件。
   暂停/继续保留计划；扩展比较需单独点击下载，切回推荐计划保留额外文件。下载后自动比较可用配置：
   实际推理测量共约 30 秒，初始化、文件校验、加载和预热时间另计。每种配置使用独立
   进程。用户明确选择后才应用；“FP32 推荐”和“实测最快”分别标注。
4. 从弹出面板打开“分析文本”，粘贴至少 50 个英文单词。无需网站权限即可看到分数、
   四类概率及分段覆盖。过短文本不评分，其他语言明确显示不支持。
5. 在普通网页选择“分析此页面”，只授权当前文档的一次运行；自动分析需要另行授予
   网站权限。设置中撤权后，对应的已打开框架停止评分。隐藏标记不会撤权，全局默认
   自动分析设置仍可能被单独网站规则覆盖。
6. 设置中可更改运行配置、重跑/取消 benchmark、停止/恢复引擎、设置空闲卸载、清除
   缓存、切换仅内存缓存。手动停止须手动恢复；空闲卸载在下次分析时自动加载。
   单纯轮询状态不会唤醒模型或延长保留时间。
7. 报告包括模型标识、版本、覆盖信息及分数解释。默认不包含原文、标题或网址；可在
   设置中单独开启。文本分析页的原文导出另有可见开关。推理不上传浏览内容。
8. 重启浏览器/电脑后，浏览器按需启动组件并复用有效的配置选择，无需日常运行终端，
   不安装开机后台服务。ZIP 插件升级需要替换解压目录并重新加载，商店插件由浏览器
   更新；本地组件另有更新按钮。
9. 使用设置中的完整卸载操作，先确认组件、模型等本地文件清理，再移除插件。
   直接从浏览器移除插件不会删除本地组件。下载包、手动解压目录、剪贴板历史、系统
   或浏览器日志不在删除保证之内。路径和备用清理方法见
   [使用指南](user-guide.zh-CN.md) 与 [文件和权限清单](footprint.md)。

PDF 请分别测试自动打开开关的两种状态；自动接管只针对已授权来源和新打开的文档。
完整 PDF.js 阅读器也可直接选择或拖入文件，无需文件网址权限。Chrome 自动接管本地
文件还需开启浏览器的文件访问开关。“打开原文”在本次导航绕过自动接管。Firefox 原生
阅读器不能插入提示，请使用工具栏入口。PDF 分析和报告会标明当前加载页面的范围，
不将局部结果称为整份文档评估。原文重读等联网例外，以及用新文本检验真实引擎离线
运行的步骤，见[联网核实指南](network-privacy.md)。

本地集成验证使用临时浏览器配置和 Native Messaging 测试组件，命令见
[英文版](reviewer-guide.en.md)。它验证接口和流程，不代表真实模型速度或检测准确率。
发行脚本会用 `scripts/verify-release.py` 检查生成的 Chrome/Firefox ZIP；审核时还应
检查最终上传包，不能使用已预授权全部网站的 `output-test`。JS/WASM 均随插件打包。
