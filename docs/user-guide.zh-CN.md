# 安装和管理 Anagram

[English](user-guide.en.md) · [文件与权限清单](footprint.md)

界面随浏览器语言显示英文或简体中文。Anagram 使用电脑上的本地组件运行 EditLens。
首次安装时按引导运行一次命令，之后日常使用、设备选择和组件管理都在插件内完成。

从 [0.4.1 发行页](https://github.com/CoderBak/anagram/releases/tag/v0.4.1) 下载浏览器插件包。
发行包中的安装命令使用配套的安装脚本和本地组件；普通源码构建仍会显示“尚未发布”提示，
不提供可误导用户的复制按钮。

## 1. 安装插件

**上架前以 ZIP 分发：** 将 Chrome 插件 ZIP 解压到准备长期保留的文件夹，打开
`chrome://extensions`，启用“开发者模式”，点击“加载已解压的扩展程序”，选择包含
`manifest.json` 的文件夹。这里选择的是解压后的文件夹。安装后不要移动它，否则开发版
插件 ID 可能变化，需要重新注册本地组件。ZIP 内无需另设模型或终端安装流程。

**从 Chrome 商店安装：** 商店页面发布后，点击“添加至 Chrome”，确认浏览器的权限
提示。插件文件由 Chrome 管理。

两种方式都会打开同一首次设置页。默认没有任何网站访问权限。必需权限为 storage、
activeTab、contextMenus、scripting 和 nativeMessaging；开启某个网站或全部网站时再申请
网站访问权限。

Firefox 使用专门的 Firefox 构建。开发阶段可以在 `about:debugging` →“此 Firefox”→
“临时载入附加组件”中选择 `manifest.json`，但此临时安装会在浏览器重启后失效。
要长期安装，需要发布经过 Firefox 签名的安装包。

## 2. 首次安装本地组件

首次设置页识别系统和浏览器，提前说明下载体积，并提供“查看安装脚本”和“复制安装命令”。
命令绑定当前插件版本和准确的插件 ID。macOS/Linux 用户粘贴到终端运行；Windows 用户
粘贴到 PowerShell。无需管理员权限，也不要求预先安装系统 Python。

安装器放置私有运行环境和程序，并向浏览器注册本地组件。保持设置页打开，它会重试连接。
命令完成后可以关闭终端，插件随后显示模型下载进度、已下载字节数和暂停/恢复按钮。
已有且校验通过的文件会复用。全部模型文件约 **4.07 GB**，运行依赖和下载临时空间另计。
无需 Hugging Face 登录，但仍必须遵守原模型的 **CC BY-NC-SA 4.0** 许可、署名和非商业
使用条件。

## 3. 比较性能并选择配置

下载完成后自动开始 benchmark。默认 **30 秒指全部组合合计的推理计时预算**，不是从点击
到结束的总耗时；模型加载和预热会单独显示阶段，也会额外花时间。测试使用内置样本文本，
不会读取当前网页作为 benchmark 输入。

页面列出可用设备、运行后端和精度，以及单条文本延迟、批量吞吐、采样到的进程/加速器内存。
无法测到的数据会显示不可用，不会记为零。推荐配置限定 FP32；FP16 可以自行选择，INT8
明确标注为实验性精度。点击“使用所选配置”后才开始推理，选择会保存在本地。
之后授权一个网站，或使用单次分析操作即可体验。

## 4. 日常使用和电脑重启

打开浏览器并使用 Anagram 时，浏览器自动启动已注册的本地组件，不需要再开终端、手动
启动服务或配置开机常驻。有效的设备选择会直接复用，不会每次重跑 benchmark。
如果之前主动停止了引擎或暂停了下载，这个选择也会保留；到设置页点击启动/恢复即可。

设置页支持更改配置、重跑/取消 benchmark、停止推理、删除模型和重新下载。
主动删除模型后，下次打开浏览器不会偷偷重新下载。当前同一组件目录只允许一个活动的本地
宿主持有；另一个浏览器或配置文件需要等原浏览器断开，避免同时加载两份模型或并发清理。

## 5. 升级

ZIP 安装：把新版本插件覆盖到**原解压文件夹**，再在 `chrome://extensions` 点击重新加载。
商店安装：由 Chrome 管理插件更新；如果更新等待本地连接结束，可点击插件的更新重载操作，
或重启 Chrome。

本地程序在设置页点击“更新本地组件”。兼容的模型文件和设备选择会复用；模型或硬件信息
变化时可能需要重新比较。更新失败会显示错误。Windows 可能打开独立的维护窗口，必须等待
它给出实际结果，不能把窗口已启动当成更新成功。

## 6. 删除模型或完整卸载

“删除模型文件”释放权重和未完成下载，保留程序。“完整卸载 Anagram”会先询问确认，删除
属于本组件的文件和注册记录；macOS/Linux 在确认本地清理完成后再移除插件。Windows 需
观察独立清理窗口，确认成功后手动移除插件。取消确认不会执行删除。

直接使用浏览器的“移除”只清理插件及浏览器内数据，无法触发本地程序卸载，所以模型和本地
组件会留下。如果已经这样操作，可以重新安装同一插件后使用清理入口，或使用本地组件的
手动卸载命令。自己下载的 ZIP 和解压后的插件文件夹也需要自行删除。

## 文件位置

| 位置 | 内容 |
| --- | --- |
| 自己选择的解压目录 | 开发者模式使用的插件文件，使用期间应保留 |
| 浏览器用户配置目录 | 商店安装的插件、设置、只含哈希和结果的评分缓存 |
| macOS/Linux：`~/.anagram` | 私有 Python 和依赖、程序与启动器、模型和未完成下载、设备选择与性能数据、组件状态和注册记录 |
| Windows：`%LOCALAPPDATA%\Anagram` | 同类本地文件，以及 Windows 启动与维护程序 |
| 浏览器 NativeMessagingHosts 目录或 Windows HKCU 注册项 | 允许此插件启动本地组件的小型注册记录 |

精确注册路径见[文件清单](footprint.md)。安装和维护还会使用操作系统临时目录；浏览器/系统
日志、备份、用户保存的 ZIP 和源码目录不在完整卸载的删除承诺内。网页原文不会持久化保存。

首次实现面向 Apple Silicon macOS、受支持的 Linux x64/ARM64 和 Windows x64。
Windows ARM64、自定义 Chrome 用户目录及其他 Chromium 浏览器还需要另行适配。
Windows 实现仍需要 Windows CI 和发布前人工验证，不能以 macOS 测试代替。
